# Переход на типизированную настройку кампаний

## Подготовка и применение после аудита 11.09.2026

Недостающие сведения, включая бюджет, выяснить в начале задачи. Затем
самостоятельно подготовить и проверить полный план и назначение отчёта.
Перед записью MCP-клиент запрашивает согласие через elicitation на конкретный
логин и полный хеш плана. `confirmation` остаётся техническим одноразовым токеном
целостности и сам по себе не разрешает запись. Решение, хеш, время и имя клиента
сохраняются в журнале. Участие человека обеспечивает доверенный интерфейс клиента;
сервер фиксирует `client_attested`, а не удостоверенную личность человека.

Запуск и возобновление показов требуют отдельной явной команды пользователя.
Preview, live preflight, независимый readback, резервные копии и проверки
публикации сохраняются. `BLOCK`, неполные выборки и дубли останавливают запись.
Разрешения среды исполнения и границы доступа это правило не изменяет.

Новый основной сценарий состоит из `direct_campaign_plan` и
`direct_campaign_apply`. Он заменяет свободную передачу объектов Direct API на
версионированный бизнес-план `direct_campaign_bundle_v1` и создаёт нативные
`UnifiedCampaign` через JSON API v501.

## Что изменилось

Старый `direct_campaign_setup` удалён из MCP: путь смешивал TextCampaign v5
и ResponsiveAd v501. Используйте typed bundle для нативной UnifiedCampaign.
План и применение доступны только при `YD_MODE=campaign_setup`.
Подтверждение одноразовое, действует 30 минут и связано с логином и хешем плана.
Старые фразы подтверждения и старые preview после обновления нужно получить заново.

Новый bundle создаёт отдельные кампании Поиска и РСЯ, а при `office=true` —
отдельную кампанию Карт и списка организаций. Компилятор добавляет выбранные
по бизнесу минус-фразы (`negative_keyword_policy`, с версии политики 1.5.0),
снимок исключённых площадок, кампанийный tracking-профиль, обязательный
автотаргетинг и разрешает две бюджетные стратегии: `maximum_clicks` и
`maximum_conversion_rate`. Для второй требуется `goal_id`, присутствующий в
`priority_goals`; средняя CPA не задаётся.

В legacy-профиле диапазон 2 000–5 000 в неделю остаётся агентской рекомендацией. Бюджет вне
диапазона создаёт `WARNING`, которое нужно явно перечислить в
`manual_checks.acknowledged_warning_rules`; это не безусловный потолок. Если
`weekly_budget` пропущен, может применяться `YD_DEFAULT_WEEKLY_BUDGET`.
Для новых бизнес-профилей этот диапазон не применяется: нужны явные доли
в общем client_budget. Актуальный стартовый состав и ориентир 30 000 RUB в месяц
возвращаются в direct_policy.planning_defaults; см. `direct://kb/policy-profiles`.

## Максимум кликов без Метрики — политика 1.8.2

Для `maximum_clicks` счётчик и бизнес-цели необязательны: `counter_ids` и
`priority_goals` можно опустить или передать пустыми массивами. Компилятор
не отправляет пустые `CounterIds`/`PriorityGoals` и не подставляет фиктивную
цель. Если цели не выбраны, `goals_reviewed`, каталог целей и
`allow_unverified_goals` не требуются. Счётчик без выбранных целей допустим.
Если бизнес-цели указаны, сохраняются проверка счётчика, ручное подтверждение
целей и live-проверка каталога. Для `maximum_conversion_rate` по-прежнему
обязательны счётчик и явный `goal_id` из `priority_goals`.

Основание: [UnifiedCampaign.add](https://yandex.ru/dev/direct/doc/ru/campaigns/add-unified-campaign):
`CounterIds` необязателен, `WB_MAXIMUM_CLICKS` не требует `GoalId` или
`PriorityGoals`. Проверено 09.09.2026.

## Безопасный порядок

1. Получить регионы через `direct_regions`; при выбранных бизнес-целях —
   каталог через `direct_goal_catalog`.
2. Сформировать bundle и вызвать `direct_campaign_plan` — этот шаг не обращается
   к write-методам.
3. Исправить все `BLOCK`; каждое допустимое `WARNING` явно подтвердить по ID
   правила.
4. Вызвать `direct_campaign_apply` без `confirmation`. Сервер повторно проверит
   регионы, цели (если задан `goal_catalog_campaign_id`) и дубликаты имён.
5. Самостоятельно проверить весь preview; отдельное согласие не запрашивать.
6. Повторить вызов с неизменным bundle и точной одноразовой confirmation.
7. Проверить `readback.verified`, compliance-аудит и локальные JSON-артефакты.

Показы не запускаются: сервер не вызывает `resume`, а readback отдельно
проверяет, что созданные кампании не находятся в состоянии `ON`. Если создание
оборвалось, ответ сохраняет известные ID и имеет статус `partial`; повторять
весь bundle нельзя.

## Каркас bundle

С версии политики 1.6.0 этот каркас нужно дополнить `semantic_plan`, обоснованиями
`semantic` каждой группы, выбранными ключами и объявлениями. Полная схема новых
полей и пример: `direct://kb/structure-semantics`. Пустые группы ниже — обозначение
места заполнения, а не готовый валидный план.

```json
{
  "name": "Клиент | Услуга",
  "start_date": "2026-09-05",
  "weekly_budget": {"search": 3000, "network": 4000},
  "region_ids": [213],
  "counter_ids": [12345],
  "priority_goals": [{"goal_id": 77, "value": 1500}],
  "office": false,
  "manual_checks": {
    "goals_reviewed": true,
    "regions_verified": true,
    "landing_pages_verified": true,
    "acknowledged_warning_rules": []
  },
  "channels": {
    "search": {"groups": []},
    "network": {"groups": []}
  }
}
```

Каждый канал должен содержать хотя бы одну группу. Полная форма групп и
объявлений видна в preview и в описании параметров MCP-инструмента.

## Компактные варианты из одного шаблона

Если кампании отличаются только каналом или настройками, вместо повторения
групп используйте `campaign_template` и минимум два `campaign_variants`:

```jsonc
{
  "campaign_template": {
    "groups": [/* полные общие группы с ключами и объявлениями */]
  },
  "campaign_variants": [
    {"channel": "search", "name_suffix": "РФ", "region_ids": [225]},
    {"channel": "search", "name_suffix": "СНГ", "region_ids": [149, 168, 159]}
  ]
}
```

Шаблон может содержать все поля канала. Вариант целиком заменяет только
`name`, `name_suffix`, `region_ids`, `weekly_budget`, `budget_approved` или
`strategy`; `groups` в варианте запрещён. После разворачивания действует тот же
валидатор и формируется тот же `plan_hash`, что у эквивалентного явного bundle.
Preview также показывает `api_units_estimate`, а результат write-операции —
фактический журнал `units_usage`.
