# Автотаргетинг, корректировки, ретаргетинг

## Возрастные ограничения и интересы аудитории — политика 1.9.0

`age_min` принимает 0, 18, 25, 35, 45, 55; `age_max` — 17, 24, 34, 44, 54 или
null (без верхнего ограничения). Границы должны совпадать с возрастными группами
API. Например, `age_min:25, age_max:54` создаёт −100% для AGE_0_17, AGE_18_24,
AGE_55. Независимый readback сверяет все исключения. Ответ BidModifiers.add
содержит массив `Ids`; исполнитель сохраняет и учитывает каждую корректировку.

Интересы необязательны и выбираются для конкретной кампании. MCP не задаёт
отраслевые аудитории по умолчанию: названия и ID интересов хранятся в клиентском
плане. Если `audience_interest_ids` отсутствует, условия по интересам не создаются.

В группе РСЯ можно указать `audience_interest_ids` (1–10 уникальных ID из
Dictionaries.AudienceInterests, только SHORT_TERM) и `audience_priority`
(LOW/NORMAL/HIGH, по умолчанию NORMAL). Такие группы отдельные: без ключей,
автотаргетинга и offer_retargeting. Долгосрочные и ANY интересы в этом варианте
ЕПК не поддерживаются. До подтверждения preflight проверяет ID и длительность
по живому каталогу и показывает названия интересов.

Исполнитель создаёт RetargetingList типа AUDIENCE с одним правилом ANY,
затем привязывает AudienceTarget к созданной группе. Он не использует InterestId
для мобильных приложений. ID обоих объектов сохраняются при частичной ошибке;
повторять весь пакет нельзя. Readback проверяет группу, ID, интересы, приоритет,
доступность и отсутствие параллельных ключей. Усечённые ответы не считаются успехом.

## Автотаргетинг

**Обязателен для ЕПК на Поиске и в Картах** (с 15.01.2024 включён и в ранее запущенных кампаниях), в каждой группе нужна хотя бы одна категория запросов. Для кампаний только в РСЯ отключается полностью.

Пять категорий запросов: **целевые** (объявление точно отвечает запросу), **узкие** (запрос уже объявления), **широкие**, **альтернативные** (заменяемый товар), **сопутствующие**. Отдельно настраиваются запросы с упоминанием своего бренда, брендов конкурентов и без брендов.

- Работает **параллельно с ключевыми фразами в равном приоритете**, а не «в довесок».
- Ставка на поиске по умолчанию — средневзвешенная по кликам от ставок группы; можно задать вручную, рекомендуется держать сопоставимой со ставками ключевых фраз.
- Разбор статистики: Мастер отчётов с группировкой по «Тип условия показа» и «Категория запроса», смотреть конверсии и CPA отдельно по каждой категории.
- Официальная позиция: любое сужение таргетингов режет охват; отключать категории только по подтверждённой неэффективности.
- Старую рекомендацию полностью отключать автотаргетинг на Поиске применить
  нельзя: актуальный API требует хотя бы одну категорию. Безопасный старт MCP —
  Exact и Narrow, без альтернативных, сопутствующих, широких запросов и брендов
  конкурентов; расширение делается только по накопленной статистике.

## Корректировки ставок

**Не суммируются, а перемножаются последовательно.** Ставка 15 ₽ с корректировками −40% (мужчины 18–24), +30% (мобильные), +200% (Москва) = 15 × 0,6 × 1,3 × 3 = 35,1 ₽.

| Корректировка | Диапазон | Уровень |
|---|---|---|
| Целевая аудитория (ретаргетинг) | −100%…+1200% | кампания/группа |
| Пол и возраст | −100%…+1200% | кампания/группа |
| Устройства | −100%…+1200% | кампания/группа |
| Погода | −100%…+1200% | группа |
| Платёжеспособность (топ 1%, 2–5%, 6–10%) | −100%…+1200% | кампания/группа |
| Уровень трат в категории | −100%…+1200% | кампания/группа (интернет-магазины) |
| Регион показа | −90%…+1200% | только кампания |
| Видеодополнения | −50%…+1200% | кампания/группа |
| Эксклюзивное размещение | 0…+1200% | кампания (нужно ≥8 быстрых ссылок) |
| Цена конверсии / ДРР / цена клика в группе | −99%…+1200% | только группа |

Особенности: −100% исключает показы (для всех типов устройств сразу так сделать нельзя); при попадании под несколько условий ЦА применяется максимально повышающая; изменение корректировки ЦА применяется с задержкой до 180 минут; для автостратегий целевые показатели (CPA, ДРР) пересчитываются с учётом коэффициентов.

**На старте корректировки не ставить** — сначала накопить статистику, иначе они мешают обучению.

Что выставлено в кабинете на самом деле, показывает `direct_account_settings`
(секция `bid_modifiers`): уровень, тип, сырой коэффициент в `bid_modifier`,
изменение относительно базы в `adjustment_percent`, `effect` и `enabled`.
Поле `percent` сохранено как совместимый alias сырого коэффициента.

## Ретаргетинг и сегменты аудитории

- Условие — комбинация целей/сегментов Метрики и сегментов Яндекс Аудиторий: **от 1 до 50 правил отбора**, в правиле от 1 до 250 целей или сегментов.
- **На поиске ретаргетинг работает через логическое «И»** с ключевыми фразами или автотаргетингом: показ идёт только тем, кто попадает и под условие ретаргетинга, и под условие показа. В сетях — самостоятельно.
- Практика eLama: ретаргетинг вести **отдельными кампаниями без других таргетингов**, иначе статистика перемешивается.
- Гиперсегментация аудиторий (новые клиенты / лояльные / «тёплые» с персонализированными офферами) даёт агентствам снижение CPA на 20–30%.
- Какие условия заведены в кабинете и годятся ли они в таргетинг — `direct_account_settings`, секция `retargeting_lists`: `scope` разделяет условия для таргетинга и только для корректировок, `available` показывает, доступно ли условие сейчас. Правила отбора тул не возвращает, они смотрятся в интерфейсе.
