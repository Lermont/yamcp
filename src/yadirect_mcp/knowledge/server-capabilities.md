# Возможности сервера и чего он не делает

Сверка практик Директа с тем, что тулы этого сервера физически умеют. Читать до того, как обещать пользователю настройку «по чек-листу».

## Что есть

- **Чтение:** `direct_list_clients`, `direct_campaigns`, `direct_report`, `direct_read_report`. Этого хватает на всю донастройку — см. «Рецепты отчётов для донастройки» (`direct://kb/report-recipes`).
- **Запись:** `direct_campaign_setup`, доступен **только при `YD_MODE=campaign_setup`**. Двухфазный: первый вызов без `confirmation` возвращает preview, второй — с точной фразой `CREATE CAMPAIGN <client_login>`. Кампания создаётся **выключенной**, `resume` не вызывается.
- `campaign` и `ad_groups` уходят в API почти как есть: валидация проверяет обязательные поля и запрещает `Id` / `CampaignId` / `AdGroupId`, а остальные валидные поля `CampaignAddItem` и `AdGroupAddItem` (`NegativeKeywords`, `TimeTargeting`, `DailyBudget`, `ExcludedSites`, `TrackingParams`) передаются без потерь.

## Ограничения

1. **Клиент ходит на `https://api.direct.yandex.com/json/v5`, а не на v501.** Создаётся `TextCampaign`, который Директ переводит в ЕПК в режиме совместимости. Напрямую ЕПК не создать: план с `UnifiedCampaign`, `SmartCampaign`, `DynamicTextCampaign`, `CpmBannerCampaign`, `MobileAppCampaign` отвергается валидацией. Недоступны раздельные стратегии Search/Network, `PlacementTypes`, `PriorityGoals`, форматы `ShoppingAd` / `ListingAd`. Подробности — «Типы кампаний и ЕПК» (`direct://kb/campaign-types`).
2. **`StartDate` обязателен и не может быть в прошлом**, формат `YYYY-MM-DD`.
3. **Обязателен `BiddingStrategy` или `PackageBiddingStrategy`** в `TextCampaign`. Деньги — в микроединицах, см. «Контракт записи в Direct API» (`direct://kb/api-contract`).
4. В каждой группе обязательны `Name`, непустой `RegionIds` и непустой массив `Ads`; в `TextAd` — `Title`, `Text`, `Mobile` (`YES`/`NO`) и `Href` либо `TurboPageId`.
5. **Дополнения и изображения сервер не создаёт.** Быстрые ссылки, уточнения и картинки живут в отдельных сервисах API (`Sitelinks`, `AdExtensions`, `AdImages`), которых у сервера нет. Передать можно только уже существующие в аккаунте `SitelinkSetId`, `AdExtensionIds`, `AdImageHash`. При этом заполненные дополнения — обязательный пункт чек-листа, значит их придётся добирать в интерфейсе.
6. **Корректировки ставок отдельным сервисом (`BidModifiers`) не задаются** — только то, что принимает `AdGroupAddItem`.
7. **Операция не атомарна.** При обрыве ответ содержит созданные ID и ошибки по каждому объекту: повторять нужно только недостающее, не весь план целиком.
8. За один запуск — не более 1000 групп; API принимает не более 1000 объектов на вызов.

## Автотаргетинг: рабочий обход

Автотаргетинг обязателен для поисковых групп и передаётся как **псевдо-фраза**. Достаточно добавить строку `"---autotargeting"` в массив `Keywords` группы: валидация пропустит её как обычную ключевую фразу, а `Keywords.add` создаст условие показа с `CriteriaType: AUTOTARGETING`. Один автотаргетинг на группу. Ставку через этот тул задать нельзя (`KeywordBids.set` не реализован) — Директ возьмёт средневзвешенную по группе.

## Порядок работы при запросе «настрой кампанию»

1. Собрать вводные по «Чек-листу первичной настройки» (`direct://kb/launch-checklist`): сайт, цель, гео, бюджет, сроки, стратегия, счётчик и цели Метрики, минус-слова, семантика, тексты.
2. Проверить лимиты символов и фраз (`direct://kb/tech-limits`) **до** вызова API: ошибка вызова стоит 20 баллов.
3. Вызвать `direct_campaign_setup` без `confirmation` и показать preview человеку целиком.
4. Только после явного согласия повторить вызов с точной фразой подтверждения.
5. Показы не включать — активацию делает человек.
