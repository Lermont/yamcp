# Media Targeting · клиентские отчёты

Готовый HTML-шаблон с двумя видами отчётов: о результатах рекламы и о настройке. Исходные данные, оформление и поведение разделены. Собранный HTML работает автономно, без сервера, внешних библиотек, счётчиков и запросов к рекламным кабинетам.

## Открыть

- `dist/index.html` — основной единый отчёт; «Настройка» и «Статистика» переключаются в левом меню.
- `dist/statistics.html` — отдельный демонстрационный экспорт статистики; не заменяет основной клиентский отчёт.
- `dist/setup.html` — отдельный демонстрационный экспорт настройки; не заменяет основной клиентский отчёт.

Откройте файл двойным щелчком в Chrome или Edge. Для отправки достаточно одного HTML-файла: логотип, стили, сценарий и данные уже внутри. Публичная сборка использует системный шрифт Arial или sans-serif и не загружает шрифты из сети.

Данные примера вымышлены. Плашка «Демонстрационный отчёт» присутствует в HTML и при печати.

## Возможности

- Периоды и сравнение с предыдущим периодом, фильтры «Все каналы / Поиск / РСЯ».
- Единый расчёт итогов, стоимости клика и цели, кликабельности и доли израсходованного бюджета.
- График по дням: клики, расход, достижения выбранной цели; сравнение можно отключить.
- Таблица дневных значений для чтения графика без мыши.
- Поиск кампаний, сортировка, экспорт текущей таблицы в CSV для Excel.
- Восемь срезов статистики: ключевые фразы, поисковые запросы, площадки РСЯ,
  группы, объявления, регионы, устройства, пол/возраст. Таблицы с поиском,
  сортировкой, страницами по 20 строк и CSV всех найденных строк.
- Срезы объединяют одинаковые запросы, площадки, регионы и аудитории по выбранным
  кампаниям. Значения CTR/CPC/CPA пересчитываются из сумм. Тексты объявлений —
  текущий снимок; неизвестные значения и ограничения охвата указаны явно.
- Ссылка сохраняет выбранный вид, период и канал. Для локального файла предлагается передать сам HTML.
- Настройка: структура, параметры кампаний, фразы и исключения, пример объявления, варианты заголовков и описаний, проверки, дальнейшие шаги.
- Мобильная версия, меню, управление вкладками стрелками с клавиатуры, состояния фокуса.
- Кнопка PDF вызывает штатную печать браузера. Выберите «Сохранить как PDF», формат A4; отключите колонтитулы браузера и включите фоновую графику. Печатается выбранный вид отчёта с текущими фильтрами; настройки и методология раскрываются автоматически. Дневная таблица в PDF скрыта, график сохранён.

## Правило MCP: один отчёт на весь проект

При настройке создавайте единый `index.html` с «Настройкой» и «Статистикой» в
левом меню. До накопления результатов `periods` и `daily` могут быть пустыми:
раздел статистики покажет, что результаты появятся после запуска. Для начальной
модели используйте `views: ["setup", "statistics"]`.

Затем дополняйте **эту же модель и этот же HTML** статистикой. Сохраняйте настройку,
все прошлые периоды и каноническую ссылку `https://bi-data.ru/elama/<direct_login>/`.
Перед обновлением читайте существующий отчёт и данные, сохраняйте резервную копию.
Один период и пары дата/кампания должны обновляться по ключам без дублей.
`build.py` собирает переданный JSON целиком; он **не объединяет** старые и новые
выгрузки автоматически, поэтому сначала объедините модель с сохранённой историей.

Правило записано в общих инструкциях MCP, политике 1.8.0 и ресурсе
`direct://kb/client-report`. Старый генератор `/create/` остаётся вспомогательной
выгрузкой настройки; агент отдельно собирает и проверяет основной единый отчёт.

Для регулярной сборки кодом используйте `direct_client_report` или
`python -m yadirect_mcp.report_runner refresh-all`: регистрация реальной модели,
сбор статистики, сохранение версий и ограниченная сводка для ИИ.
Подключение описано в [инструкции MCP](../../src/yadirect_mcp/knowledge/client-report.md).
Это отдельный слой над автономным `build.py`; CLI не устанавливает расписание
и не публикует файлы. Для простого офлайн-шаблона сам MCP не требуется.

Каждый новый `update` собирает детальные срезы автоматически. Для уже собранного
текущего периода есть `direct_client_report(action="enrich", client_login=...)`
или CLI `enrich --client ...`: дневные цифры, настройка и прошлые периоды сохраняются.
Старые опубликованные отчёты без отдельного запуска не перегенерируются.

У периодов могут быть `campaignIds` (выборка кампаний), `dataRevision` и
`insight: {title, text, dataRevision}`. Вывод показывается только для всех каналов
и при совпадении версии данных; при фильтрации отображается числовая сводка.
Дробные цели сохраняются в интерфейсе с точностью до двух знаков.

## Новый отчёт

Нужен Python 3.10 или новее, без дополнительных пакетов.

1. Скопируйте `example-data.json` в файл своего проекта.
2. Замените все данные клиента, показатели, периоды, работы, планы и настройки. Удалите ненужные демонстрационные записи.
3. Установите `demo: false` после замены всех демонстрационных данных.
4. Соберите отчёт:

```powershell
python D:\mcp_direct\templates\client-report\build.py D:\reports\client-data.json --out D:\reports\client-report.html
```

Для отдельного демонстрационного экспорта (основной клиентский отчёт остаётся единым):

```powershell
python D:\mcp_direct\templates\client-report\build.py D:\reports\client-data.json --view statistics --out D:\reports\statistics.html
python D:\mcp_direct\templates\client-report\build.py D:\reports\client-data.json --view setup --out D:\reports\setup.html
```

Ключ `views` в данных управляет доступными вкладками; первая вкладка открывается по умолчанию. Для отчёта только по настройке допустимы пустые `periods` и `daily`. Это отдельный шаблон; существующий генератор `src/yadirect_mcp/creation_report.py` не переключён на него автоматически.

## Формат данных

`example-data.json` — полный пример всех полей.

| Блок | Содержание |
|---|---|
| `client` | Название, описание проекта, короткая подпись и монограмма |
| `campaigns` | Список кампаний с уникальным строковым `id`, названием, каналом `search` или `network`; параметры и тексты для настройки |
| `periods` | Периоды, источник, дата обновления, бюджет по кампаниям, условия измерения, работы и планы |
| `daily` | Одна строка на дату и кампанию: `spend`, `impressions`, `clicks`, `conversions` |
| `setup` | Дата и статус настройки, заголовок, задача, факты, следующий шаг, тексты объявлений и проверки |

### Числа и отсутствие данных

- `spend` — **рубли с НДС**, не микрорубли API. Комиссия агентства в этот показатель не входит.
- Полный набор `daily` должен содержать запись для каждой кампании на каждый день выбранного периода, включая дни без показов. Для измеренного отсутствия активности используйте нули.
- `null` — неизвестное значение. Ноль и отсутствие данных не взаимозаменяемы.
- Если отсутствует день или кампания, общий итог не рассчитывается; на графике отсутствующие дни отображаются разрывом. Полные отдельные кампании остаются видимыми в таблице.
- Стоимость рассчитывается как сумма расходов, делённая на сумму кликов/целей, а не как среднее дневных стоимостей. При нулевом знаменателе выводится прочерк.
- Проценты сравнивают суммы двух периодов. При разной длине периодов это не сравнение среднесуточных значений. График совмещает дни по порядку, точные даты есть в дневной таблице.
- `periods[].budget` — план на выбранный период, по ID кампаний. Не недельный лимит и не баланс кабинета. Неизвестный план — `null` или отсутствующее поле.

### Измерение целей

Для данных по выбранной цели:

```json
"measurement": {
  "available": true,
  "goal": "Отправка формы",
  "attribution": "автоматическая атрибуция",
  "comparable": true
}
```

Все кампании периода должны иметь одинаковый смысл цели и сопоставимые условия атрибуции. Если цели или модели кампаний различаются, сначала подготовьте сопоставимую выборку или отдельные отчёты. Шаблон не проверяет настройки Директа через API.

`comparable: false` отключает сравнение по целям и их стоимости с предыдущим периодом. Достижения цели не называются уникальными заявками или продажами.

Для отчёта только по трафику:

```json
"measurement": {
  "available": false,
  "note": "Отслеживание целей не настроено. Оцениваем привлечение трафика."
}
```

В этом случае вместо целей и их стоимости показываются показы и стоимость клика. Колонки целей и соответствующий переключатель графика скрываются.

### Настройка

`setup.title` и `setup.status` заполняются фактическим состоянием проекта: подготовлено, ожидает модерации, запущено и т. п. Тексты всех проверок и отметки `complete` задаются явно, а не выводятся из наличия поля или предположений.

Параметры кампаний — снимок на дату `setup.date`, не история настроек за статистический период. Предпросмотр объявления схематичен и не обещает конкретный вид в рекламной сети. Быстрые ссылки в макете — подписи элементов, а не ссылки на действующий сайт.

Если в `setup.adVariants` несколько объявлений, шаблон отдельно сравнивает их
быстрые ссылки (`sitelinks`) и уточнения (`callouts`). Полностью совпадающий
непустой список, включая порядок элементов, выводится один раз в блоке
«Общие настройки объявлений» под параметрами кампаний и не повторяется в
карточках объявлений. Различающиеся списки остаются у соответствующих объявлений;
пустые списки не выводятся. Если хотя бы у одного объявления список отсутствует
или пуст, он не считается общим. При одном объявлении дополнения остаются в его
карточке. Формат исходных данных менять не нужно.

## Файлы

- `template.html` — каркас документа и футер.
- `styles.css` — внешний вид, адаптивность и печать.
- `report.js` — отображение данных и интерактивность.
- `build.py` — проверка JSON и сборка автономного HTML.
- `example-data.json` — демонстрационные данные для замены.
- `make_demo.py` — повторное создание именно вымышленных примеров.
- `assets/` — оригинальный логотип; необязательные локальные шрифты не распространяются.
- `QA.md` — результаты проверки.

Сборка не публикует отчёт и не изменяет рекламные кампании. При размещении клиентского отчёта используйте согласованный адрес `https://bi-data.ru/elama/<direct_login>/`; логин берётся из таблицы соответствия клиента. `noindex` ограничивает индексацию, но не закрывает доступ к опубликованному файлу.
